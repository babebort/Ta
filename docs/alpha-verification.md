### 8. PaddleOCR 校验卡死修复

- 根因是 `/usr/bin/zipinfo -1` 对 24,567 个文件产生约 2.58 MB 输出；旧实现先等待子进程退出、再读取 Pipe，Pipe 缓冲区写满后父子进程互相等待。
- 子进程输出已改为独立临时文件，校验、解压、健康检查和 OCR 进程均增加超时与任务取消处理。
- SHA-256 校验现在按已读取字节持续上报 0–90% 进度，路径安全检查完成后上报 100%。
- 2,500 文件的大列表回归包在 5.25 秒内完成；取消 30 秒健康检查的测试在 1.16 秒内结束，没有残留子进程。
- 真实 184.9 MB PaddleOCR 发行包已在一次性 Application Support 目录完整走通“复制 → SHA-256 → 24,567 文件路径检查 → 解压 → 健康检查 → 安装”，总耗时 89.42 秒。

### 10. 长截图自动滚动与预览方向修复

- 自动滚动不再按 420 ms 采集 tick 累计重复帧；改为只在真实发出下一次滚动时结算上一次是否新增内容，慢动画产生的多张重复帧不会提前耗尽停止预算。
- 一旦拼接到新增内容，无进展次数立即清零；连续 2 次滚动均未增加页面内容后停止。正常滚动节奏改为 300ms 级，匹配不确定时才自适应等待、最长 900ms；每次逻辑滚动发送 2 个有界滚轮事件，删除固定 1.3 秒等待造成的低速问题。
- 到底判断已与接缝拼接解耦：独立运动检测器比较滚动前后的中间主体区域，忽略固定标题栏、底部输入框和小范围动画；只有连续两次确认主体无位移才停止。主体已移动但接缝尚未稳定时显示等待，不再把拼接失败误当作到底。
- 自动滚轮从超大的 pixel 增量改为标准 line 单位，每次限制为 3–10 行，减少 Safari、微信和 WebView/Electron 对单次大滚轮值处理不一致的问题。
- 滚动距离按选区高度的 48% 计算，并限制为 180–520 pixel；滚动事件通过兼容 WebView/Electron 的全局 HID 路径发往选区中心，随后安全恢复原鼠标位置；若检测到用户正在移动鼠标，则不会覆盖用户的新位置。
- 修复最终 AppKit/PNG 预览仍垂直翻转的问题：合成器取消整张画布翻转，并通过真实 `NSBitmapImageRep → PNG → NSBitmapImageRep` 显示路径验证页面顶部、页面底部和分段顺序。
- 新增自动滚动状态机、滚动距离、单帧方向、两帧方向和分段预览顺序测试；仍需在微信、Safari/Chrome、Codex 与 WorkBuddy 真实内容中做最终手工回归。

### 18. Snipaste 风格文字输入与手涂马赛克
