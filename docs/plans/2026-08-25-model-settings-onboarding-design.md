# 「拓」AI 模型配置体验优化设计

## 目标

让第一次接触 API 的用户也能在一分钟内完成 AI 识图配置，并且明确知道：还缺什么、配置保存在哪里、当前是否真的可用。

## 方案比较

### A. 继续使用参数表

保留当前 Form，只调整间距和文案。改动小，但用户仍需要理解 Provider 协议、Base URL、模型名和兼容矩阵，无法解决核心问题。

### B. 完整分步向导

每次只展示一个步骤。最适合首次配置，但老用户修改模型需要来回切换，且不适合设置页中的日常维护。

### C. 新手引导 + 高级设置折叠（采用）

在一个页面内提供明确的三步主路径，并将协议、地址和预留文字模型收进高级设置。首次使用直观，熟悉 API 的用户也不会失去控制能力。

## 页面结构

1. **状态总览**：标题“让 AI 看懂截图”，显示“未完成 / 可以使用”、完成项数量和下一步提示。
2. **复用已有配置**：检测到截图翻译已经配置时，允许一键在本机复用 DeepSeek 地址、模型和 Keychain 凭证。
3. **选择服务商**：DeepSeek、OpenAI、OpenRouter、Claude、Gemini、Azure、自定义七个预设。预设自动填写协议和服务地址；DeepSeek 同时填写项目当前使用的视觉模型。
4. **填写凭证**：API Key 单独成为主步骤，明确说明只存入 macOS Keychain，覆盖升级不会丢失。
5. **选择视觉模型**：只把真正用于 AI 识图的视觉模型放在主路径，并提示模型必须支持图片输入。
6. **选择默认任务**：使用自然语言“AI 识图后默认做什么”，不要求用户理解 Prompt 模板。
7. **高级设置**：折叠展示协议、服务地址和预留文字模型。
8. **完成操作**：主按钮“保存并测试”，次按钮“仅保存”。测试期间显示进度，结束后给出成功或可执行的失败原因。

## 状态与错误

- 缺 API Key：提示“粘贴服务商提供的 API Key”。
- 缺视觉模型：提示“填写一个支持图片输入的模型名称”。
- 地址错误：在高级设置入口和底部操作区同时显示错误。
- 测试失败：配置仍然保存，提示“配置已保存，但连接测试失败”，避免用户误以为输入丢失。
- 已配置：显示绿色“可以使用”，并提示可在截图工具栏点击“AI 识图”。

## 验收标准

- 新用户不展开高级设置，也能完成 DeepSeek 预设配置。
- 页面始终明确显示配置完成度和下一步。
- 保存和连接测试是可区分的两个动作。
- API Key 继续使用原 Keychain account；已有 Key 和模型配置不迁移、不清空。
- 键盘可聚焦全部输入与按钮，状态不只依赖颜色表达。
- 覆盖升级后原有配置继续存在。
