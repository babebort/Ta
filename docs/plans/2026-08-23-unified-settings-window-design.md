# 设置窗口 UI 统一设计

日期：2026-08-23

## 问题

应用同时存在两种设置窗口宿主：

1. `SettingsWindowController` 创建的普通自定义窗口，`TabView` 在内容顶部显示为纯文字胶囊式标签栏。
2. SwiftUI `Settings` Scene 创建的系统设置窗口，会把相同 `TabView` 转换成带 SF Symbol 图标的 macOS 原生设置工具栏。

主页与菜单栏按钮打开第一种；macOS 应用菜单“设置…”和 `⌘,` 打开第二种，因此用户会看到同一份设置内容呈现出两种 UI，误以为新版界面被还原。

## 方案

- 保留用户偏好的 SwiftUI `Settings` Scene 和现有 `SettingsView`，以系统设置工具栏展示各页图标。
- 主页“完整设置”和菜单栏“设置”统一触发应用菜单中由 SwiftUI 注册的设置命令，打开同一个系统设置窗口。
- macOS 应用菜单“设置…”与 `⌘,` 继续使用系统自动提供的同一入口。
- `SettingsWindowController` 只作为极旧系统或系统动作不可用时的兜底，不再是正常入口。

## 验收

- 主页“完整设置”显示顶部带 SF Symbol 图标的原生设置工具栏。
- 菜单栏“设置”打开同一个窗口。
- macOS 应用菜单“设置…”打开同一个窗口。
- `⌘,` 打开同一个窗口。
- 任意入口重复调用时，进程中只有一个设置窗口。
