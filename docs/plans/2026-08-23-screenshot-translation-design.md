# 截图翻译功能设计

日期：2026-08-23

## 目标

在不破坏现有截图、OCR、钉图和标注流程的前提下，增加三种翻译结果：

1. 文字翻译：截图后识别文字，翻译并复制到剪贴板。
2. 全文图片翻译：在原文字区域覆盖目标语言，保留原图尺寸和主要视觉结构。
3. 双语图片翻译：保留完整原图，在图片下方追加原文与译文面板，避免行内双语造成遮挡。

## 入口与交互

- 新增全局快捷键 `⇧⌥⌘6`，直接执行“文字翻译并复制”。
- 通用截图的选区工具栏新增“翻译”按钮。
- 点击“翻译”后弹出模式选择，默认项由设置控制：
  - 翻译文字并复制
  - 全文翻译图片
  - 双语翻译图片
- 图片翻译完成后打开现有标注编辑器预览，用户可以继续标注、复制或保存。
- 通用截图的默认动作中增加“翻译文字并复制”。

## 模型与数据流

默认配置使用 DeepSeek：

- API：`https://api.deepseek.com/chat/completions`
- 文字模型：`deepseek-v4-flash`
- 视觉模型：`deepseek-v4-flash-vision-exp`
- API Key：独立存入 macOS Keychain，不写入 UserDefaults、源码和日志。

文字翻译的主路径为：Apple Vision 本地 OCR → DeepSeek 文字模型翻译 → 剪贴板。这样速度快、成本低，并保留文字框位置。低置信度或无文字时，只有在设置开启后才把本次选区发送给视觉模型完成识别与翻译。

图片翻译使用 Apple Vision 的文字框，在一次批量模型请求中按稳定 ID 翻译各行。全文模式在本机按文字框覆盖并重排译文；双语模式不改原图，在下方追加双语面板。视觉模型不会自由重绘整张图片，以免修改图标、人物或版式元素。

## 设置

- 服务地址
- 文字模型
- 视觉模型
- API Key（Keychain）
- 源语言：默认“自动检测”，允许任意文本
- 目标语言：默认“简体中文”，允许任意文本
- 默认翻译模式
- 低置信度时允许视觉模型增强
- 文字模型与视觉模型连接测试

## 错误和隐私

- 未配置 Key、模型返回空内容、JSON 不完整、网络超时分别显示可理解错误。
- 模型调用期间不覆盖用户新复制的内容。
- 图片上传时在结果胶囊明确显示“正在使用视觉模型”。
- 图片模式无法获得可靠文字框时，不生成位置错误的图片，提示改用文字翻译。
- 远程地址必须使用 HTTPS；只有 localhost/127.0.0.1 允许 HTTP。

## 验收

- 英文截图可通过快捷键翻译为中文并复制。
- 源语言和目标语言修改后，提示词与结果跟随设置变化。
- 工具栏“翻译”可选择三种模式。
- 全文图片包含译文且保持原图尺寸。
- 双语图片保持原图不变，并在下方追加成对文本。
- Key 不出现在偏好设置文件或日志中。
- DeepSeek 两个模型具备请求契约测试；渲染器具备尺寸和像素方向测试。

## 2026-08-23 实际模型联调

- `/models` 返回 `deepseek-v4-flash`、`deepseek-v4-pro` 和 `deepseek-v4-flash-vision-exp`。
- `deepseek-v4-flash` 成功把英文测试句翻译为简体中文。
- `deepseek-v4-flash-vision-exp` 成功读取测试截图中的指定中文状态文字。
- 联调 Key 仅在交互式进程内存中使用，没有写入本文档或命令行参数。
