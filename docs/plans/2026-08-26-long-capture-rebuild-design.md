# 拓长截图重构设计

## 目标

用户只指定“从哪里开始”和目标滚动区域，拓负责持续采集到真实底部。默认路径必须同时覆盖浏览器、Codex、WorkBuddy 和普通 macOS App，不要求安装扩展，也不占用或反复移动鼠标。

## 为什么当前实现不可靠

当前实现把一次长截图视为固定节拍的“截图 → 发滚轮事件 → 全图灰度匹配”。它缺少三个可靠性来源：

1. 没有锁定真实滚动容器，只把滚轮事件发到选区中心；嵌套滚动区、焦点变化或不可滚动位置会吞掉事件。
2. 单一全图匹配容易被重复聊天卡片、固定侧栏、固定输入框和大面积留白误导。
3. “截图未变化”同时承担页面尚未响应、滚动事件未生效和真正到底三种含义，因此会提前结束或重复滚动。

## 采用方案

### 1. 起点与采集区域

沿用自由框选，但重新定义含义：框的顶部是输出起点，框的宽度是输出宽度，框的底部是当前可视采集底线。用户可以从 Codex 某条消息顶部开始框到聊天区底部；第一帧只保留这个起点以下内容，后续帧继续补充到底。

### 2. 滚动目标锁定

开始采集时，用辅助功能 API 从选区中心命中 UI 元素，向父级查找可滚动元素或垂直滚动条，并记录目标应用 PID。滚动优先采用可访问滚动条的标准值推进，这可以读取当前位置、判断真实底部，也不依赖鼠标位置。目标不暴露滚动条或不允许设置值时，回退到发送像素滚轮事件，但仍固定在已解析的目标点。

### 3. 确认式状态机

每次只允许一个滚动事务：

`稳定帧 → 记录滚动进度 → 发出滚动 → 等待视觉或滚动值变化 → 页面稳定 → 拼接成功 → 下一次滚动`

只有以下条件同时满足才算到底：滚动值已到最大值，或连续两次滚动值不变；并且连续稳定帧视觉内容不变。页面有变化但暂时无法拼接时，不继续滚，也不宣称到底；改用更小步长在当前事务内恢复匹配。

### 4. 拼接策略

相邻帧只在“旧帧底部 ROI ↔ 新帧顶部 ROI”搜索正向位移。将有效宽度划为多个竖向带，分别计算行梯度指纹并投票；固定侧栏、固定标题栏或单个重复区域不能主导结果。候选必须同时通过：方向一致、预测位移邻域、至少两条内容带支持、次优候选分离度和重叠区误差验证。接缝采用保守策略：宁可保留极少重复行，也不删除未确认文字。

### 5. 浏览器路径

Chromium 的 CDP `Page.captureScreenshot(captureBeyondViewport: true)` 是网页原生整页截图的最佳路径，但普通用户浏览器默认没有开放调试端口，也不能覆盖第三方 App。因此首版不把 CDP 作为依赖。未来可在用户主动安装浏览器扩展或开启调试能力时作为无接缝加速器，失败自动回到通用路径。

## 错误处理

- 找不到可访问滚动容器：仍允许事件回退，并明确显示“通用滚动模式”。
- 页面滚动但拼接不确定：缩小步长并在当前事务内重试，不追加可疑帧。
- 动态内容持续变化：暂停并保留已验证内容，不输出已知损坏的图。
- 超长输出：按像素高度安全分段，保持从上到下顺序。

## 验收标准

1. Codex：从指定消息顶部开始，输出不得包含该消息上方内容，连续内容不重复、不吞行，自动运行到聊天底部。
2. 浏览器：从页面中间指定起点开始，输出只包含起点以下内容，并到达页面底部。
3. 嵌套滚动区：滚动的是选区对应容器，不是外层窗口或其他列表。
4. 重复内容：重复卡片、代码块、白底段落不得造成向上跳转或错误大位移。
5. 到底判断：页面尚未响应或懒加载时不提前结束；真正到底后有限次确认并结束。
6. 无感操作：自动采集不移动用户鼠标，不切换当前 App，不抢键盘焦点。
